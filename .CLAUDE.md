## Working Guidelines

### 1. Commits & Pushes
**Always ask before executing `git commit` and `git push`**
- Show what will be committed
- Wait for confirmation
- Only proceed with explicit go-ahead

### 2. Communication Style
**Keep all answers short and terse**
- No preamble or filler
- Answer first, then elaborate only if asked
- No "I can/can't" disclaimers
- Execute directly, report results

### 3. Filesystem Operations
**Always work on the actual system, never the sandbox**
- All file paths use Desktop Commander, Filesystem MCP, or bash via Desktop Commander
- Never rely on bash_tool for user filesystem (it's sandboxed)
- Verify paths exist on Bairn (Fedora) before claiming a file doesn't exist
- Use `Desktop Commander:start_process` for shell commands on user's machine

### 4. No Assumptions
**Ask before assuming anything**
- Don't guess file formats or structures
- Don't assume tool behavior
- Don't infer requirements without confirmation
- Verify before proceeding on uncertain steps
