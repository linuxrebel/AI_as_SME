## Working Guidelines

### 1. Commits & Pushes
**Always ask before executing `git commit` and `git push`**
- Show what will be committed
- Wait for confirmation
- Only proceed with explicit go-ahead

### 2. Communication Style
**Keep all answers short and terse**
- No preamble or filler
- Answer first, then elaborate only if asked
- No "I can/can't" disclaimers
- Execute directly, report results

### 3. Filesystem Operations
**Always work on the actual system, never the sandbox**
- All file paths use Desktop Commander, Filesystem MCP, or bash via Desktop Commander
- Never rely on bash_tool for user filesystem (it's sandboxed)
- Verify paths exist on Bairn (Fedora) before claiming a file doesn't exist
- Use `Desktop Commander:start_process` for shell commands on user's machine

### 4. No Assumptions
**Ask before assuming anything**
- Don't guess file formats or structures
- Don't assume tool behavior
- Don't infer requirements without confirmation
- Verify before proceeding on uncertain steps

### 5. Clarifying Questions
**Ask for clarification when ambiguity exists**
- If a request has multiple interpretations, ask which one
- If unclear what "better" or "best" means, ask for criteria
- If unsure about scope or priority, confirm before proceeding
- Example: "Replace ASCII diagrams — do you want SVG, <pre> tags, or something else?"

## Lessons Learned This Session

### File Operations
- bash_tool runs in sandbox and cannot access user's `/home/james/` files
- Desktop Commander:start_process with shell commands works for user filesystem
- Always verify file existence via Desktop Commander before assuming missing
- Use `tail`, `head`, `grep` via Desktop Commander for file inspection

### Markdown to HTML Conversion
- ASCII art diagrams in markdown backticks get mangled during HTML conversion
- Solution: Use `<pre>` tags with monospace styling for ASCII diagrams
- Box-drawing characters (┌┐└┘├┤) need proper rendering context

### Attribution & Licensing
- All files need SPDX headers at top
- Author metadata should be explicit (Author: name, Copyright: year name)
- HTML footers provide clear attribution visible to end users
- License file needs copyright notice and full terms upfront

### Documentation Best Practices
- Keep diagrams in markdown source but handle rendering in HTML carefully
- Use consistent styling for code blocks vs diagram blocks
- Always include back-links in multi-page HTML guides
- Footer attribution should appear on every major page
